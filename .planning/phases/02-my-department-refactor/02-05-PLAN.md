<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Uruchom migrację dept_type w Supabase</name>
  <what-built>
    Plan 01 stworzył plik migracji SQL dodający kolumnę dept_type (enum: logistics | archiving | grants) do tabeli departments wraz z backfillem na podstawie nazw działów.

    Bez tej migracji routing w page.tsx (switch department.dept_type) zawsze trafi do bloku `default` — panele nie będą renderowane.
  </what-built>
  <how-to-verify>
    Opcja A — Supabase CLI (zalecana):
    ```bash
    cd admin-os
    npx supabase db push
    ```
    lub jeśli masz supabase CLI globalnie:
    ```bash
    supabase db push
    ```

    Opcja B — Supabase Dashboard:
    1. Otwórz https://app.supabase.com → Twój projekt → SQL Editor
    2. Skopiuj i uruchom zawartość pliku: supabase/migrations/20260404_add_dept_type_enum.sql
    3. Zweryfikuj: `SELECT id, name, dept_type FROM departments;` — kolumna dept_type powinna mieć wartości dla działów logistyki/grantów/archiwizacji

    Oczekiwany wynik:
    - Działy zawierające "dotacj" w nazwie → dept_type = 'grants'
    - Działy zawierające "logistyk" lub "logitech" → dept_type = 'logistics'
    - Działy zawierające "archiwizacj" lub "bieżąc" → dept_type = 'archiving'
    - Pozostałe działy → dept_type = NULL (to OK)
  </how-to-verify>
  <resume-signal>Wpisz "migracja ok" po uruchomieniu, lub opisz błąd SQL jeśli migracja się nie powiodła.</resume-signal>
</task>
